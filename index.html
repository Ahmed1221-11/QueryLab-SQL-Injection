ATTACK / UNDERSTAND / REPAIR

One login. Two outcomes.

Watch untrusted input change a database query. Then send the exact same input through a parameterized query and compare the result.

Why this works: in the vulnerable version, admin' -- closes the username string and comments out the password condition. In the fixed version, that entire input is a username value. No such user exists, so the login fails.
Fictional accounts · Loopback only · No real login session is created. Passwords are stored as plaintext only to isolate this SQL demonstration; real authentication also requires password hashing and other controls.
